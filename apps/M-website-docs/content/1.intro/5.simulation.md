A Docker container bundles a web visualizer of M (its five joints and its face) and a ROS 2 workspace. Programs you write against the simulator use the same interfaces as the physical robot.

![The M simulator: a 3D model of M beside joint-position sliders and face controls](/images/m-sim.webp)

::note
The container runs on macOS and Linux. Windows support is coming soon.
::

## Requirements

- [Docker](https://docs.docker.com/get-docker/) (Docker Desktop on macOS)
- On macOS, for audio: [Homebrew](https://brew.sh)

## 1. Download and load the container

Download [`m_robot_simulation.tar`](https://drive.google.com/file/d/1_v6k4Mm22hJko2lFNmKAJq2WWr62Tpvj/view?usp=sharing) from Google Drive, then load it into Docker. This saves the loaded image's name in `IMAGE` for step 3:

```bash
IMAGE=$(docker load -i m_robot_simulation.tar | sed -n 's/^Loaded image: //p')
echo "$IMAGE"
```

## 2. Set up audio (macOS only)

M speaks through the simulator. To hear it on a Mac, run a PulseAudio server on the host that Docker containers can reach. On Linux, skip to step 3.

### Install PulseAudio

```bash
brew install pulseaudio
```

### Configure it

Keep PulseAudio running even when idle, which Docker needs:

```bash
mkdir -p ~/.config/pulse
cat > ~/.config/pulse/daemon.conf << 'EOF'
exit-idle-time = -1
scache-idle-time = -1
EOF
```

Expose a TCP server that containers reach through `host.docker.internal`:

```bash
cat > ~/.config/pulse/default.pa << 'EOF'
.include /opt/homebrew/etc/pulse/default.pa

### Allow Docker containers to connect over TCP
load-module module-native-protocol-tcp auth-ip-acl=127.0.0.1;172.16.0.0/12;10.0.0.0/8 auth-anonymous=1
EOF
```

### Start it and check

```bash
pulseaudio -k || true
pulseaudio --daemonize=yes
pactl info
```

The output should include `Server Name: pulseaudio` and your speakers as the default sink, for example `MacBook_Air_Speakers`.

::tip
If PulseAudio fails to start or behaves oddly, clear its stale runtime files, then repeat **Configure it** (this also removes the two files created there):

```bash
rm -rf ~/.config/pulse/* ~/.pulse ~/.pulse-cookie \
       ~/Library/Preferences/org.pulseaudio.pulseaudio.plist
rm -rf /tmp/pulse-* /var/tmp/pulse-* 2>/dev/null
```
::

## 3. Start the container

```bash
docker run -it --rm \
  -e PULSE_SERVER=host.docker.internal \
  -p 3000:3000 \
  -p 9090:9090 \
  -v $HOME/.config/pulse/cookie:/root/.config/pulse/cookie \
  --name m_sim \
  "$IMAGE"
```

This opens a shell inside the container. Check that audio reaches your speakers:

```bash
aplay /usr/share/sounds/alsa/Front_Center.wav
```

## 4. Start the visualizer

In the container's shell:

```bash
cd /root/m-sim-ui
npm run dev -- --host 0.0.0.0 --port 3000
```

Then open [http://localhost:3000](http://localhost:3000) in your browser.

## 5. Run a ROS 2 program

In a second terminal, open another shell in the running container and start the demo:

```bash
docker exec -it --privileged m_sim bash
cd /root/m_ws
ros2 launch storyteller sim_test.launch.py
```

## 6. Mirror ROS 2 in the visualizer

In the visualizer, switch **Mode** from **Sim Only** to **ROS2 Mirror**. The simulated robot now follows the program running in ROS 2.
