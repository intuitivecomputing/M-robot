title: Raspberry Pi Setup
description: Flash the robot's Raspberry Pi, install M's dependencies with one script, and calibrate the servos.

Every M runs on a Raspberry Pi 5. This page takes the Pi from a blank microSD card to calibrated servos. It expands steps D-1 and D-4 of the [build guide](https://intuitivecomputing.github.io/M-robot/build-guide#page-45).

## What you need

- The Raspberry Pi 5 from the [bill of materials](https://intuitivecomputing.github.io/M-robot/bill-of-materials), with its screen connected (build guide step D-1)
- A microSD card, 32 GB or larger
- A computer with an SD card reader, on the same Wi-Fi network as the robot
- Internet access on that network: the setup script downloads packages

The commands for your computer are for a macOS or Linux terminal. On Windows, use WSL or Git Bash.

## 1. Flash the operating system

1. Install [Raspberry Pi Imager](https://www.raspberrypi.com/software/) on your computer and insert the microSD card.
2. For the device, choose **Raspberry Pi 5**.
3. For the operating system, open **Raspberry Pi OS (other)** and choose **Raspberry Pi OS (Legacy, 64-bit)**.
4. For the storage, choose your microSD card.
5. When Imager offers to customise the OS, set:
   - **Username and password**: give each robot its own username, such as `m-robot-1`, and write it down. You'll use it every time you connect.
   - **Wi-Fi**: the name, password, and country of your computer's network.
   - **SSH** (on the Services or Remote access tab): turn it on, with password authentication.
6. Write the card, put it in the robot's Pi, and power the Pi on.

::warning
Choose the **Legacy** release, which is Debian Bookworm, not the newer default: M's setup script is written for Bookworm. Avoid the **Lite** version too. M shows its face in a web browser on the screen, which needs the desktop.
::

Anyone on the robot's network can try to log in over SSH, so choose a strong password.

## 2. Copy M's files to the robot

The setup files are in the [m-robot-files](https://github.com/intuitivecomputing/m-robot-files) repository: the `setup_M.sh` script and the `m-motor-control` folder.

Find the robot's IP address: run `hostname -I` in a terminal on the robot's screen, or look the robot up in your router's list of connected devices.

On your computer, save the robot's username and IP address in a variable, replacing these with yours:

```bash
ROBOT=m-robot-1@192.168.1.42
```

Then download the files and copy them to the robot's `Documents` folder:

```bash
git clone https://github.com/intuitivecomputing/m-robot-files.git
cd m-robot-files
ssh "$ROBOT" mkdir -p Documents
scp -r setup_M.sh m-motor-control "$ROBOT":Documents/
```

The first time you connect, SSH asks you to confirm the robot's fingerprint (type `yes`), then asks for the robot's password. No `git`? Download the repository from GitHub with **Code → Download ZIP** and unzip it instead.

## 3. Run the setup script

Connect to the robot and run the script there:

```bash
ssh "$ROBOT"
cd ~/Documents
bash setup_M.sh
```

The script takes several minutes. Enter the robot's password if it asks. When it finishes, it restarts the robot, which ends your SSH session.

::note
The script first looks for an `m-motor-control.zip` and warns `Zip file not found` when there isn't one. That's expected: it uses the `m-motor-control` folder you copied.
::

### What the script sets up

| Component | What it's for |
| --- | --- |
| I2C interface | The Pi drives the servos through the PCA9685 servo driver over I2C |
| Node.js 21, via nvm | Runs the face server, which draws M's face on the screen |
| Docker | Runs M's ROS 2 software in a container. The script adds your user to the `docker` group |
| Camera stream on `/dev/video10` | The `libcamera-ffmpeg@10` service streams the Pi camera to a virtual webcam at 640×480, 30 fps, so any program can read it, including ones in Docker |
| Python environment `~/motor_env` | The servo libraries from `m-motor-control/requirements.txt` |

### Check the camera

After the robot restarts, reconnect and check the camera service:

```bash
ssh "$ROBOT"
systemctl status libcamera-ffmpeg@10 --no-pager
```

It should report `active (running)`. To see the picture, run `ffplay -f v4l2 -i /dev/video10` in a terminal on the robot's screen.

::tip
No camera on your M? Turn the camera service off:

```bash
sudo systemctl disable --now libcamera-ffmpeg@10
```
::

## 4. Calibrate the servos

Calibration moves each servo to the angle M's software treats as that joint's zero, so the parts you attach next line up with it.

Before you start:

- Connect the servo driver to the Pi and the servos to the driver (build guide steps D-2 and D-3), and switch on the 7.4 V servo power supply.
- Make sure no servo is connected to a part. If you are following the build guide, none is yet. On an assembled robot, take off the head and unscrew the neck joint pulley.

On the robot, run:

```bash
cd ~/Documents/m-motor-control
source ~/motor_env/bin/activate
python Servo_Initialization.py
```

You'll hear the servos turn, then stop. Each one moves to this angle:

| Channel | Joint | Servo | Angle |
| --- | --- | --- | --- |
| 0 | Body rotation | 270° | 125° |
| 2 | Head nod | 270° | 40° |
| 4 | Head rotation | 270° | 120° |
| 8 | Left arm | 180° | 135° |
| 10 | Right arm | 180° | 45° |

These are the `offset` values in the robot's motor configuration, `src/motor_control/config/config.json`. If you plugged a servo into a different channel, change its channel number in both `Servo_Initialization.py` and `config.json`.

::warning
Leave the robot powered on afterwards. In Part E of the build guide, you attach the parts while the servos hold these angles.
::

## Troubleshooting

- **`No I2C device at address: 0x40`, or no `/dev/i2c-1`**: the Pi can't reach the servo driver. Check the wiring from build guide step D-2: VCC to pin 1 (3.3 V), SDA to pin 3, SCL to pin 5, and GND to pin 9. Then check that I2C is on: `sudo raspi-config nonint get_i2c` prints `0` when it is.
- **No error, but the servos don't move**: the servos draw power from the driver's V+ terminal, not from the Pi. Check that the 7.4 V supply is connected and switched on.
- **`python: command not found` or `No module named 'adafruit_servokit'`**: activate the Python environment first, with `source ~/motor_env/bin/activate`.
