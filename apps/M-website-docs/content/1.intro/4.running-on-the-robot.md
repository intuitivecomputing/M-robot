---
title: Running on the Robot
description: Load M's prebuilt ROS 2 software onto the robot, show its face, and start an interaction.
---

On the robot, M's ROS 2 software comes prebuilt in a Docker image, so there is nothing to compile. The face runs beside it: a small web server on the Pi draws it, and the robot's screen shows it in a browser.

Start here once the robot is assembled and its Pi is set up with [Raspberry Pi Setup](/intro/raspberry-pi-setup). The commands below use the `ROBOT` variable from that page, and the `m-robot-files` folder you downloaded there.

## 1. Load the software image

Connect to the robot, then download the image and load it into Docker. The download is about 840 MB.

```bash
ssh "$ROBOT"
cd ~/Documents
curl -L -o m_robot_base_26.tar "https://drive.usercontent.google.com/download?id=111chPgtVpyY37OQmzvB8iJB2fWrsJZs6&export=download&confirm=t"
docker load -i m_robot_base_26.tar
```

Docker reports `Loaded image: m_base:jan_26`. If the download fails, get [`m_robot_base_26.tar`](https://drive.google.com/file/d/111chPgtVpyY37OQmzvB8iJB2fWrsJZs6/view?usp=sharing) from Google Drive in a browser, copy it to the robot with `scp m_robot_base_26.tar "$ROBOT":Documents/`, and run the `docker load` command again.

## 2. Add your API keys

M listens, speaks, and converses through cloud services:

| Service | Used for | What you need |
| --- | --- | --- |
| Google Cloud | Speech recognition and Google text-to-speech | A service-account key file (JSON) with the Speech-to-Text and Text-to-Speech APIs enabled |
| OpenAI | Text-to-speech | An API key |
| Groq | The conversation's language model | An API key |

On your computer, copy the Google key file to the robot's home folder:

```bash
scp path/to/your-google-key.json "$ROBOT":google-credentials.json
```

On the robot, create a file for the keys with `nano ~/m.env`, and add:

```text
OPENAI_API_KEY=your-openai-key
GROQ_API_KEY=your-groq-key
GOOGLE_APPLICATION_CREDENTIALS=/root/google-credentials.json
```

The last line is the key file's path inside the container, so leave it as it is. Then make the file readable only by you:

```bash
chmod 600 ~/m.env
```

::warning
Never commit API keys or the key file to a repository.
::

## 3. Start the face

M's `face_controller` node sends expressions to a face server on port 3001. Use the one in `pilot-deployment/face-server`. Copy it from the `m-robot-files` folder on your computer:

```bash
scp -r pilot-deployment/face-server "$ROBOT":Documents/
```

On the robot, install and start it:

```bash
cd ~/Documents/face-server
npm install
node server.js
```

It prints `Server running on port 3001`. Leave it running, and open a second terminal for the rest of this page.

In the second terminal, show the face full screen on the robot's display:

```bash
ssh "$ROBOT"
DISPLAY=:0 firefox --kiosk http://localhost:3001/face.html &
```

The face page loads its animation libraries from the internet, so the robot needs a connection. To close it, run `pkill firefox`.

## 4. Start M's software

In the second terminal, start the container:

```bash
docker run -it --rm --privileged --network=host \
  --env-file ~/m.env \
  -v ~/google-credentials.json:/root/google-credentials.json:ro \
  --name m_robot \
  m_base:jan_26
```

- `--privileged` gives the container the robot's hardware: the servo driver, microphone, speaker, camera, and LED.
- `--network=host` lets it reach the face server at `localhost:3001`.

You get a shell inside the container, in the ROS 2 workspace at `/root/m_ws`, ready to run.

::tip
The image includes the default motor configuration. To use your robot's own joint offsets or servo channels without rebuilding the image, copy the configuration folder to the robot from the `m-robot-files` folder on your computer:

```bash
scp -r src/motor_control/config "$ROBOT":Documents/motor_config
```

Edit `~/Documents/motor_config/config.json` on the robot, then add `-v ~/Documents/motor_config:/root/m_ws/src/motor_control/config` to the `docker run` command.
::

## 5. Run an interaction

Inside the container, start the positive psychology coach:

```bash
ros2 launch positivity_pysch_coach enhanced_conversation_interaction.launch.py
```

This one launch file starts everything the coach needs: the microphone, voice activity and turn-end detection, speech recognition, text-to-speech, audio playback, the motor, face, and LED controllers, and the conversation orchestrator.

Press Ctrl+C to stop it, and run `exit` to leave the container. The other launch commands in [Getting Started](/intro/getting-started) work the same way inside the container.

::note
To start everything automatically at boot, use the files the in-home pilot used as a starting point: `start-robot.sh`, `storytelling_robot.service`, and `setup_service.txt` in `pilot-deployment/face-server`. They were written for the pilot's own image and username, so change the image name, paths, and launch command to match your robot.
::
