Reusable chat completion wrappers for Groq and OpenAI APIs. Both follow the same interface pattern and can be swapped interchangeably in M Platform applications.

## Groq Provider

- **Module**: `m_examples.groq_llm_provider`
- **Class**: `Groq_LLMProvider`
- **Default model**: `llama-3.1-8b-instant`
- **Requires**: `GROQ_API_KEY` env var, `groq` package

### Constructor

```python
from m_examples.groq_llm_provider import Groq_LLMProvider

provider = Groq_LLMProvider(model="llama-3.1-8b-instant", temperature=0.7)
```

### `complete()` Method

```python
response = provider.complete(
    system_prompt="You are a helpful assistant.",
    user_message="Hello!",
    max_tokens=500,
    reasoning_effort="medium",  # "low", "medium", or "high"
)
```

- **`reasoning_effort`** — Only applied for reasoning models (model names containing `reasoning` or `gpt-oss`)

## OpenAI Provider

- **Module**: `m_examples.openai_llm_provider`
- **Class**: `OpenAI_LLMProvider`
- **Default model**: `gpt-4o-mini`
- **Requires**: `OPENAI_API_KEY` env var, `openai` package

### Constructor

```python
from m_examples.openai_llm_provider import OpenAI_LLMProvider

provider = OpenAI_LLMProvider(model="gpt-4o-mini", temperature=0.7)
```

### `complete()` Method

```python
response = provider.complete(
    system_prompt="You are a helpful assistant.",
    user_message="Hello!",
    max_tokens=500,
)
```

## Common Interface

Both providers share the same `complete(system_prompt, user_message, max_tokens)` signature, making them interchangeable:

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `system_prompt` | `str` | — | System message defining LLM behavior |
| `user_message` | `str` | — | User query or context |
| `max_tokens` | `int` | `500` | Maximum tokens in response |

## CLI Testing

Both modules include a `main()` entry point for quick testing:

```bash
python -m m_examples.groq_llm_provider "You are helpful." "What is ROS 2?"
python -m m_examples.openai_llm_provider "You are helpful." "What is ROS 2?"
```
