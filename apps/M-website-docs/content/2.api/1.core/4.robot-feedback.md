# Robot Feedback

Visual feedback systems including an HTTP-based face expression controller and a GPIO-based LED indicator controller. Both nodes are defined in the `m_commons` package.

## Face Controller

Subscribes to a `face_expression` topic and forwards commands to a web-based face display via HTTP POST requests. Supports two modes:

- **Expression mode** — Send a named expression (e.g., `happy`, `sad`, `neutral`)
- **Exec mode** — Send executable animation programs prefixed with `exec:` (e.g., `exec:waking_up`)

### Node Details

- **Node**: `face_controller`
- **Package**: `m_commons`
- **Entry point**: `m_commons.face_controller:main`
- **Subscribes**: `face_expression` (`std_msgs/String`)

### Parameters

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `express_url` | `string` | `http://localhost:3001/express` | URL for expression commands |
| `exec_func_url` | `string` | `http://localhost:3001/exec-func` | URL for executable animation programs |
| `request_timeout` | `double` | `2.0` | HTTP request timeout in seconds |

### Usage

```bash
ros2 topic pub /face_expression std_msgs/String "data: 'happy'"

ros2 topic pub /face_expression std_msgs/String "data: 'exec:waking_up'"
```

## LED Controller

Controls a physical LED via GPIO on Raspberry Pi using the `lgpio` library. Falls back to simulation mode when `lgpio` is not available.

### Node Details

- **Node**: `led_controller`
- **Package**: `m_commons`
- **Entry point**: `m_commons.led_controller:main`
- **Service**: `control_led` (`ControlLED`)
- **GPIO Pin**: 24

### Service Interface

The `control_led` service accepts:

- **Request**: `enabled` (`bool`) — `true` to turn LED on, `false` to turn off
- **Response**: `success` (`bool`), `message` (`string`)

### Simulation Mode

When running without GPIO hardware (e.g., on a development machine), the node logs LED state changes without attempting GPIO writes.

### Usage

```bash
ros2 service call /control_led m_interfaces/srv/ControlLED "{enabled: true}"
```

## Integration

Both the `mic_streamer` and `camera_streamer` nodes automatically call `control_led` to turn the LED on when they start and off when they shut down, providing a visual indicator that the robot is actively sensing.
