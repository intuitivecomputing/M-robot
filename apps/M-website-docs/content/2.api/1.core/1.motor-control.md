# Motor Control

The `motor_controller` node provides low-level motor control with queued keyframe execution, named motor primitives, and a legacy single-pose interface.

## Node

- **Name**: `motor_controller`
- **Package**: `motor_control`
- **Entry point**: `motor_control.motor_controller:main`

## Services

| Service | Type | Description |
| --- | --- | --- |
| `set_pose` | `SetPose` | Move joints to a target position (legacy) |
| `play_pose_sequence` | `PlayPoseSequence` | Execute queued multi-frame keyframe sequences |
| `execute_primitive` | `ExecutePrimitive` | Trigger named motor behavior functions |

## Motor Configuration

The robot has 5 configurable servo motors:

| Joint | Channel | Range (°) | Servo Range (°) |
| --- | --- | --- | --- |
| `base_rotation` | 0 | -120 to 120 | 0–270 |
| `head_pitch` | 2 | -40 to 40 | 0–270 |
| `head_yaw` | 4 | -90 to 90 | 0–270 |
| `arm_left` | 8 | -45 to 135 | 0–180 |
| `arm_right` | 10 | -45 to 135 | 0–180 |

Configuration is loaded from `/root/m_ws/src/motor_control/config/config.json`. If the file is missing, a built-in default is used.

## Available Primitives

Named motor behaviors that can be triggered via `execute_primitive`:

| Primitive | Description |
| --- | --- |
| `beat` | Rhythmic beat gesture |
| `open_encourage` | Open-arm encouraging gesture |
| `invite` | Single invitation gesture |
| `invite_double` | Double invitation gesture |
| `point_arm` | Point with arm |
| `body_shift` | Shift body posture |
| `head_tilt` | Tilt head sideways |
| `ack_nod` | Quick acknowledgment nod |
| `slow_nod` | Slow empathetic nod |
| `ReturnToNeutral` | Return all joints to neutral position |

## Keyframe Sequence Format

The `play_pose_sequence` service uses flattened 1-D arrays to stay within `.srv` constraints:

- **`at`** — Array of start times (seconds) for each keyframe
- **`duration`** — Array of durations for each keyframe motion
- **`joint_names`** — Array of joint names (length `J`)
- **`joint_angles`** — Flattened array of angles (length `N × J`)

Sequences are queued internally and executed by a background worker thread with accurate timing.

## Usage Example

```bash
ros2 service call /set_pose m_interfaces/srv/SetPose \
  "{joint_names: ['head_yaw', 'head_pitch'], joint_angles: [30.0, 10.0], duration: 1.0}"

ros2 service call /execute_primitive m_interfaces/srv/ExecutePrimitive \
  "{function_name: 'ack_nod', param_names: [], param_values: [], start_at: 0.0}"
```

## Launch

```bash
ros2 launch motor_control motor_control_exec.launch.py
```
